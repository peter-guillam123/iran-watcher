Three deadline-day fixes 7 May 2026 (morning)

Morning of 7 May: Dan flagged that the morning brief hadn't landed by 8:42am UK — the deadlines matter to him because his news days are planned around them. Three fixes in one go.

(1) Cron reliability. GitHub Actions schedule is best-effort and can be delayed by 30+ minutes during high load or skipped entirely (which is what happened today). Each edition now has a primary cron (5:30 / 14:30 UTC) and a backup cron 20 minutes later. The workflow checks if today's edition file was written in the last hour and skips the work if so — primary fires on time, backup no-ops; primary skips, backup catches it. Honest limitation: GitHub can still fail BOTH crons in a sustained outage, in which case we'd want an external scheduler hitting workflow_dispatch via the API. Two backup windows reduce the failure rate substantially without that infrastructure.

(2) Edition order — evening on top. Was: morning briefing first, evening update below. Once the evening edition has landed, it's the freshest read — that's what the reader should see first. The "Jump to" pill nav still lets you flip down to the morning briefing whenever you want.

(3) Thread click → smooth-scroll to filtered events. Was: clicking a thread filtered the events list but you still had to scroll past two edition headers, day-shape kickers and threads blocks to reach the actual filtered content. Now the click also smooth-scrolls the filter row + events section to the top of the viewport, so the active filter context (source pills + refine toggles) and the filtered events sit together at the top. Click-to-clear leaves the scroll alone — you're already where you want to be. prefers-reduced-motion respected.

Tanker Trackers added · maritime-OSINT gap (mostly) closed 15 May 2026

The 14 May ISW comparison identified maritime-OSINT as the most obvious v2 gap — vessel-name-specific reporting like the Hui Chuan seizure and Indian-livestock-carrier sinking that ISW pulled from Windward AI and Lloyd's List subscription wires. Lloyd's List Intelligence is £15k+/year enterprise pricing; Windward AI is B2B sanctions-screening at undisclosed-but-similar tiers. Not realistic.

Free workaround: Tanker Trackers via Bluesky. The private maritime OSINT team ISW themselves cite in footnotes as "Tanker Trackers" runs an active Bluesky account at @tankertrackers.com with the same content they put on X. Their editorial register is exactly what we want — visual-evidence-only, deliberately neutral on official claims. Wired in as a third Bluesky account, tier 2, no API key needed (free AT Protocol read API).

Backfill smoke test on last fortnight: 7 raw posts, 4 Iran-relevant kept after the local filter. The kept items include "Iran Oil Tanker Likely Beat US Blockade", a 25-tanker April export tally, and the LPG-blockade-evasion story. Exactly the vessel-level intel the 14 May comparison flagged as missing.

What we still don't reach: UKMTO incident advisories (their entire ukmto.org domain is WAF-403-blocked, PDFs included — only realistic path would be a headless browser, not worth the complexity), and the broader Lloyd's List + Windward analyst-grade tracking. But for the Iran-oil specific lane, Tanker Trackers is structurally the right add.

Cron hardening: four firings per edition 11 May 2026

This morning both the 05:30 UTC primary cron and the 05:50 UTC backup silently dropped — no run at all until I manually triggered one at 08:15 UTC. Dan plans his news days around the two delivery deadlines (7am and 4pm UK), so a missed morning brief is a real editorial cost, not just a cosmetic one.

The fix is more belt-and-braces: each edition now fires FOUR times spread over ~75 minutes, not two over 20 minutes. Morning crons at 05:30, 05:50, 06:15 and 06:45 UTC; evening crons at 14:30, 14:50, 15:15 and 15:45 UTC. The existing "skip if today's edition is already fresh" gate (added with the morning/evening split) means later firings no-op cleanly when an earlier one succeeded — verified working from a real run yesterday that detected the file was 2 seconds old and exited without burning Anthropic API spend. So we get robust delivery without redundant work.

GitHub Actions' scheduling is documented as best-effort — runs can be delayed by 30+ minutes during high load and occasionally skip entirely. Two consecutive crons skipping was a more severe failure than I'd planned around. Four firings should mean a ~30+ minute window of GH Actions outage is needed to miss a brief entirely; if that happens often we'll need to move to an external trigger (cron-job.org → repository_dispatch) or a watchdog workflow that escalates.

Two editions per day — morning and evening preserved 6 May 2026 (afternoon)

Was: morning run wrote data/{date}.json, evening run overwrote the same file. The morning's threads, day-shape and source mix were lost the moment the afternoon refresh fired. Dan flagged this — he wanted to keep both briefings visible on the same page, not have the morning replaced.

Now each run writes its own edition file: data/{date}-morning.json and data/{date}-evening.json. The morning briefing is the 24h catch-up read, in by 7am UK. The evening update is "what's developed since this morning" — a delta with a window starting at 05:00 UTC today, in by 4pm UK. Different editorial register, different window shape, both stacked on the same dated page.

Page layout: page header with per-edition counts, a "Jump to Morning · Evening" pill nav when both are present, then each edition's section (header + day-shape kicker + threads block). At the bottom: ONE combined events list with shared filters — deduped union of both editions' events, no event shown twice. The threads from both editions remain individually clickable; clicking either filters the combined events list.

Legacy data/{date}.json files (from before this change) render as a single unlabelled briefing — no migration script needed. The first time the morning cron fires for a date produces -morning.json; the evening cron produces -evening.json. Days that have only one edition file render only one section.

Three tweaks after Dan's first read 4 May 2026 (afternoon)

Dan loved it and asked for three small adjustments. (1) Twice-daily cron. Was once at 06:00 UTC (~07:00 BST). Now 05:30 UTC and 14:30 UTC — a morning brief in by 7am UK and an afternoon refresh in by 4pm UK, with a 30-minute lead before each deadline. Both runs land on the same dated page; the afternoon run regenerates the day's brief with whatever's new since the morning. (2) Translated badge promoted from summary to head row. The "translated" pill used to sit at the end of each summary. Two problems: the title/summary dedup pass was stripping it on most Telegram cards (because summary == title for many regime posts), and even when it survived it was post-hoc not at the scan-time moment when a reader sizes up a card. Now there's a "Translated · Persian" badge in the source row of every translated card and every translated cluster header. Accent-red treatment, named source language, visible at a glance. (3) Click a thread → auto-expand related clusters. Was: click thread → events filter, but you'd still need to manually expand each broadcast cluster to read the matching items inside. Now clicking a thread auto-expands any cluster whose children are cited by the thread. Same direction-of-action as every other "click → show me everything related" UI.

UN OCHA / ReliefWeb adapter switched on 4 May 2026

The appname registration came through this morning — TheGuardian-TestBrief-wt9es, the suffix is ReliefWeb's own. The OCHA / ReliefWeb adapter has been wired in since v1; the gate that's been blocking it since November 2025 is now lifted, and the source switches on without code changes beyond the secret rotation.

Two adapter-level wrinkles ironed out before the first run. (1) ReliefWeb's ISO 8601 parser rejects microsecond-precision timestamps — 2026-04-20T07:17:00.123456+00:00 returns 400, 2026-04-20T07:17:00+00:00 works. Strip microseconds before sending. (2) ReliefWeb publishes the same UN / ICRC / WHO releases in English, French and Spanish, so the brief was getting the same situation report three times. Added a language.code = en filter at the API level — drops the duplicates without doing a translation pass.

First-run smoke test pulled 25 unique English-language Iran-tagged reports from the last fortnight: WFP situation reports, UNHCR refugee updates, ICRC president statements, WHO escalation reports, IOM mobility reports. Tier 1 (clean API), so it sits with UK Parliament, Federal Register and OFAC at the top of the documentary stack. Closes the last named gap from the v1 scoping document.

Cluster teaser tightened, latest deduped 3 May 2026 (late)

Two related fixes after eyeballing the broadcast zone live. (1) The cluster header was rendering the latest tweet's full body as a Playfair-headline teaser, which made an IDF strike post look more visually significant than an Iran International edited headline. The teaser now drops to body register (Public Sans, 14px italic, ink-soft) and truncates hard at ~120 characters with an ellipsis. The Iran International / Times of Israel / Jerusalem Post documents above keep their proper headlines. The visual hierarchy now reads documents at headline weight, broadcasts at snippet weight, which matches the editorial weighting. (2) Expanding a multi-post cluster was showing the latest post twice — once as the teaser at the top and again as the first event card inside the expander. Dedup: when N > 1, the expander shows posts 2…N (skipping the teased latest); the expand label adapts to "Expand to read previous N-1 posts". Single-post clusters keep the post in the expander since the snippet is just a preview of it.

Broadcast layer split into military and regime sub-blocks 3 May 2026 (evening)

The previous "regime-channel layer" zone at the bottom of the brief now becomes a "broadcast layer" zone with two visually-distinguished sub-blocks. Military spokes at tier 2 (IDF + CENTCOM via X) get a thin ink rule and a "Military spokes · official-body broadcasts" caption. Regime channels at tier 4 (Khamenei, IRIB, Defa Press) keep the deep-red rule and a "Regime channels · claims, not facts" caption.

The editorial logic: documents and journalism are different units from broadcasts, regardless of provenance tier. UK Parliament Q&A, Federal Register designations, State Department press releases, gov.uk Atom items, Iran International articles, Times of Israel and Jerusalem Post headlines — all documents, render inline chronologically. IDF/CENTCOM tweets and Khamenei/IRIB/Defa Press posts — all broadcasts, cluster by handle and live in the broadcast zone at the bottom.

Times of Israel and Jerusalem Post specifically stay inline as documents — they're newspapers that happen to deliver via Bluesky. The mechanism is incidental; editorially they do reported journalism with edited headlines, the same unit shape as a State Department press release. Lumping them into the broadcast zone would mis-signal what they are.

Both sub-blocks share the existing cluster mechanism (channel name → teaser → expand). Source filter pills still hide individual clusters by source. Tier sort still splits the broadcast zone back into tier-2 and tier-4 buckets if you ask for it explicitly.

Two presentation polish fixes 3 May 2026 (afternoon)

Two small fixes after a first eyeball of the redesigned brief. (1) Twitter / Bluesky / IDF / CENTCOM cards were rendering the body text twice — title is synthesised from the first ~140 chars of the post text, and the summary is the same body with at most an attribution suffix tacked on. The renderer now drops the summary when its normalised text is a prefix or superset of the title. 100% drop rate on tweet/Bluesky cards; 65% on Telegram (drops the translated pairs that read identically); 0% on Iran International where the RSS feed has proper distinct fields. (2) The day-shape sentence at the top of the brief was set in 21px Playfair, weight 500, which competed with the threads block at 19px right below. Drops to 15.5px Public Sans, weight 400, ink-soft colour. The accent-red kicker label still carries the visual weight; the sentence sits underneath quietly, supporting the threads.

Brief presentation pass — five changes for scale 3 May 2026

The brief is going to get noisier. Bluesky added 20 items today, OCHA / ReliefWeb is one appname registration away, UK Parliament will go from zero to ~30 items a day when it's back from recess. So a presentation pass before the volume lands.

Five changes, in priority order. (1) "Today's shape" — a single one-sentence kicker at the very top of every brief, generated from the same Opus call that produces the threads. Names the most consequential developments concretely, with figures and named bodies. The 5-second skim a 7am editor reads before scrolling. (2) Telegram regime-channel clusters — the 35-items-a-day Khamenei + IRIB + Defa Press layer collapses into one block per channel, with the latest item as a teaser and an expander for the rest. Inline-chronological they were swamping the primary-source layer; now they sit in their own zone at the bottom of the brief with a thin accent rule and a "REGIME-CHANNEL LAYER" caption. (3) "fig." marker — small monospace badge on cards that contain specific verifiable figures (40+ sites, 45 vessels, $344m, 27%). Detection is regex-based, runs after the translation pass so it catches the English version of Persian / Arabic posts, and is paired with a "With figures only" filter toggle. The "writeable from" cards in one click. (4) "Primary sources only" toggle — hides tiers 3 + 4 (Iran International + regime channels) so the reader can see what governments and multilateral bodies are saying directly. Single button replacing five-pill-deselects. (5) Clickable threads — each thread already cites the events it clusters; clicking the thread title now filters the events list below to just those items. The topical-filter mechanism without inventing a flat topic taxonomy.

Five filter axes now live and orthogonal: source family, sort (date/tier), primary-only, figures-only, current-thread. Each answers a distinct question. No two slice the same data the same way. The synthesis pass also auto-bumps from a 5-thread to a 7-thread cap on days with more than 60 items, since 5 themes is too coarse a partition over a sitting-day brief.

Times of Israel and Jerusalem Post via Bluesky 3 May 2026

Both English-language Israeli newspapers run active Bluesky accounts (timesofisrael.com and thejerusalempost.bsky.social) that auto-post their headlines with an external embed pointing to the article URL. The AT Protocol exposes a fully public, unauthenticated read API — no key, no free-tier slot, no third-party scraper. sources/bluesky.py pulls the latest 100 posts per account, extracts the article URL from each post's external embed (or falls back to the Bluesky permalink for image-only posts like quote cards), and emits at tier 2 alongside State Department and gov.uk Atom.

Smoke test on a 2-day window: 161 posts fetched across both accounts, 41 kept after the local Iran filter — the right kind of cull. The kept items are precisely the headlines a UK defence correspondent wants surfaced (Trump's "renew strikes if they misbehave", Iranian officer warning of likely war, Hezbollah rocket fire, the Spirit Airlines bankruptcy "amid Iran war price fuel surge").

The honest limitation: this closes the English Israeli press gap, not the Hebrew one. ISW's tactical-operational lift comes from Mako, YNet (in Hebrew), Channel 12 and KAN — none of which are meaningfully on Bluesky. The named Hebrew-press reporters whose scoops ISW cites (Manni Fabian, Barak Ravid, Yossi Melman) all created BS accounts in 2024 and effectively stopped posting; they're back on X now. The Hebrew layer stays in the v2 pile, achievable via polite scrape with translation, and the About page is honest about it.

One bug shipped en route: the local keyword filter dropped IDF posts that said "southern Lebanon" without naming Hezbollah, since "lebanon" wasn't in the IRAN_TERMS list. Fixed by trusting the curated feed (needs_local_filter=False) — these are official military-spox broadcasts during a live Iran/Hezbollah war, on-beat by definition.

Cron shifted to 07:00 UK time 2 May 2026

Was 06:00 + 18:00 UTC twice a day. Now once a day at 06:00 UTC, which lands at 07:00 BST through UK summer. In UK winter the brief arrives at 06:00 UK, an hour earlier than the nominal 07:00 — GitHub cron doesn't follow DST. Early is fine for an editorial product.

Five threads + translation pipeline 1 May 2026 (evening)

Two Claude API passes added on top of the collection pipeline. The first translates Persian, Arabic and Hebrew Telegram items via claude-haiku-4-5 with a structured-output schema, cached on disk by event id so re-runs are free. The second is a single claude-opus-4-7 call per run that clusters the day's events into up to five themed two-sentence blurbs.

The synthesis system prompt is strict about NOT editorialising — no "this suggests", no "amid", no "raising concerns", no "experts say". Each thread cites at least two event ids; threads that draw on tier-4 (regime-channel) or military-spox claims get an "includes claims" badge so a Khamenei broadcast in a thread is visibly flagged. Combined cost: roughly £0.04/run.

A backfill workflow retro-fits both passes onto historical archive days without re-fetching events from sources, since most of the underlying RSS feeds don't reach back far enough to make re-fetching meaningful.

Telegram regime-channel adapter 1 May 2026 (afternoon)

Three Iranian regime channels via the public t.me/s/ web preview: Khamenei's office (rahbar_enghelab_ir), IRIB state broadcaster (iribnews), and the IRGC-affiliated Defa Press (defapress_ir). v1 prototype 1 May 2026

First end-to-end run. Six source adapters wired up, filter and de-dup working, daily HTML page rendering. The morning brief for 1 May has 38 items across UK Parliament, Federal Register / OFAC, US State Department, UN Press, IAEA and the UK FCDO / No 10 / MoD via gov.uk's Atom feeds.

Honest gaps from day one: ReliefWeb is wired but waits on an appname registration that ReliefWeb tightened in November 2025. That's exactly the kind of national-record-of-record material a UK tip-sheet should be surfacing, and most of it never makes the wires.
